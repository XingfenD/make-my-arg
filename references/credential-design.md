# 凭据设计——方式菜单

> 步骤 3 的谜题分配与步骤 5 的谜题审计共用这份选单：每个门禁、关键词锁或登录账号，
> 从这里选一种设计方式。规范规则在 `references/guardrails.md`（R3、R4、R10）；谜题
> 类型总表（A–M）在 `references/design-playbook.md` §3；门禁的机械规则（哈希契约、
> 挂载形态、失败提示）在 `references/structure/components.md` §3。规则 ID `(Rn)` 引自
> `references/guardrails.md`。

## 总原则

三种东西不要混：

- **线索值按设计逐字出现。**关键词表要求每个键逐字出现在同一受众的某个可达页面文案里
  （M1）；推导题的原材料就是那段文案。出现不是泄漏。
- **派生串的完整形态绝不落在任何页面上。**部件分散在不同公开页，串不在任何页：组装
  本身就是谜题，且静态站点的 HTML 会送达每一个访客，没有服务端鉴权
  （`tools/check-credentials.mjs` 断言零明文）。
- **泄漏按四类判定**：答案本身、换个说法复述、推导规则、答案的位置
  （`workflow/05-puzzle-audit.md` Q4；步骤 8 对建成的目录树重扫）。印没印出不是判据。

## 方式菜单

| 方式 | 何时选 | 答案怎么到达玩家 | 检查器证明什么 | 禁止事项 |
|---|---|---|---|---|
| 0 初始凭据（给定） | 系统容器的第一道门：入场，不是谜题 | 入口仪式页或剧内欢迎文书（新员工通知 / 系统欢迎信）直接给出账号 + 密码 | 仍是 `data-expect-hash` 门禁；`check-solvable` 逐字溯源到给出页（0 跳，合规） | 写进名册 / 索引 / 搜索可达的公开页；用它守护深层区域 |
| 1 逐字线索（0 跳） | 检索型谜题；关键词门禁（M1） | 关键词逐字写在可达页面文案里 | `check-solvable` 逐字匹配并点名来源页 | 公开索引携带受限区 URL（R8） |
| 2 生活痕迹推导（1–2 跳） | 默认方式：密码即人物推理（R3） | 线索页给痕迹（本命年帖 → 1977），值不印在门禁页 | `check-solvable` 溯源到页面文案 | 推导规则贴在门禁页（R4）；推理链超过 2 跳 |
| 3 部件拼装（派生账号） | 系统容器的非初始账号（R10） | 部件分散在不同公开页，玩家拼出完整串 | `check-credentials`（部件 + 规则 + 零明文）＋ `check-reachability`（可解） | 完整串出现在任何页面；为让检查变绿而印出 |
| 4 多字段组合 | 档案 / 内网查询（H 型；容器 D） | 每个字段各有线索源，全部命中才开 | 每个字段一个 `data-expect-hash`，全部匹配 | 两个部件放在同一页（零跳） |
| 5 古典密码变换 | 值已可读，再加一层转码（波利比奥斯 / 摩斯 / 书密码） | 页面给出密文与对照物，玩家做变换 | 变换在客户端校验；Q4 确认变换规则不剧透 | 对照表、密文与答案同页 |
| 6 通配叙事门禁 | 情绪节拍，不校验任何秘密 | 输入即通过（`data-expect-any`） | 走图不为它找哈希；NOTE 必须为空 | 未声明的通配（R4）；把有秘密的题也做成通配 |

两条注记：

- **第一道门不是谜题。**方式 0 的存在理由是入场（容器 B/C/D 的核心幻想），不按步骤 5 的
  Q1 必要性标准衡量；谜题预算从第二道门起算。初始密码取系统默认值的形状（工号、入职年份、
  固定口令、要求首登修改的临时串），不用随机串。
- **知识检索型**（type I）是方式 2 的变体：答案在站外，GDD 声明 type I，线索指向一次站外搜索。
